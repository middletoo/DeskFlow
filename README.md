# DeskFlow

[English](README.en.md) · [中文使用指南](docs/USER_GUIDE.zh-CN.md) · [下载安装](https://github.com/middletoo/DeskFlow/releases) · [开发构建](docs/DEVELOPMENT.md)

**快捷调起，轻量常驻。**

Windows 原生桌面工具，将独立文件搜索、长期剪贴板历史，以及截图、本地 OCR、原图翻译和录制放在一个托盘程序中。

三个全局快捷键随时调起，列表向下滚动继续加载，剪贴板点击浮动预览，译文直接显示在截图对应位置。原生 C++ 与 Windows API，无内嵌浏览器运行时；索引及历史存磁盘，缓存有界，OCR 与录制按需启动。

## 资源占用：与 Everything 实测对比

### 这台电脑的实际运行观察

保留正在使用的配置、索引和历史，连续观察约 61.72 秒；CPU 按 32 个逻辑处理器整机归一，两边各统计两个现有进程。采样期间没有发起测试搜索。

| 程序 | 平均 CPU（整机） | 平均私有内存 | 平均工作集 |
| --- | ---: | ---: | ---: |
| DeskFlow 主程序 + 索引进程 | 0.45% | 40.29 MiB | 47.44 MiB |
| Everything 两个现有进程 | 2.97% | 1677.25 MiB | 1665.01 MiB |

**在这次实际运行观察中，Everything 占用约 1.64 GiB 私有内存，明显高于 DeskFlow 的约 40 MiB。** 这是当前实例的观察，覆盖范围不同：DeskFlow 约 57.5 万个条目，仍标记后台构建/校准；Everything 此前用户界面截图约 1,760 万个对象，本次未确认当前精确数量。CPU 表示这一分钟的平均值，不能等同于长期待机水平，也不能据此认定相同索引规模下有相同差距。

只公开汇总数值，不公开真实文件名、路径、历史或用户桌面截图。详见[实际观察与测试条件](docs/PERFORMANCE.md)。

### 同目录的小规模待机基准

同一台 Windows x64 电脑、32 个逻辑处理器，两者索引**同一个合成目录中的 12,000 个文件、60 个子目录**。建库完成后，同时采集三轮各约 60 秒的待机数据；DeskFlow 统计主程序和索引进程合计，Everything 统计该独立实例。

**这是隐藏界面的文件索引待机基准。** 两边均未显示或绘制主界面，没有运行 OCR、翻译或录制；DeskFlow 测试模式关闭剪贴板读取及全局快捷键，以免访问本机内容或占用用户按键。它不代表完整日常使用的资源占用。

| 程序（x64） | 平均 CPU（整机） | 平均私有内存 | 平均工作集 |
| --- | ---: | ---: | ---: |
| DeskFlow 0.3.3（两个进程合计） | 0.0003% | 10.41 MiB | 29.57 MiB |
| Everything 1.4.1.1030（一个进程） | 0.0000%¹ | 6.25 MiB | 20.84 MiB |

两者在此基准中待机 CPU 均接近零；**Everything 在这个小规模文件索引场景中的内存更低**。DeskFlow 的表中数据不包含真实剪贴板历史、已绘制界面或截图任务。本次没有测量搜索延迟、首次建库性能、全盘 NTFS/MFT 模式或千万级索引，不能据此推断这些场景的性能。

¹ 表示采样区间没有可测出的进程 CPU 时间增量，并非完全不执行代码。私有内存与含共享系统页的工作集是不同指标；MiB 为 1,048,576 字节。详见[测试条件、逐轮结果与复测方法](docs/PERFORMANCE.md)。

## 下载与启动

[Releases](https://github.com/middletoo/DeskFlow/releases) 提供已编译的 **Windows x64、x86、ARM64** 程序。

- **portable.zip**：完整解压后运行 `DeskFlow.exe`，保留旁边的 `DeskIndex.exe` 和 `DeskOCR.exe`。
- **setup.zip**：完整解压后运行 `Install-DeskFlow.cmd`，包含本地 OCR、原图翻译需要的 MSIX 包身份。
- 大多数 Intel/AMD 电脑选 x64；32 位 Windows 选 x86；Windows on Arm 选 ARM64。无需单独安装 VC++ 运行库。

可用 `SHA256SUMS.txt` 校验下载。当前验证版使用固定的开发者自签名证书，首次安装可能请求 UAC。

支持 Windows 10 2004+ / Windows 11；ARM64 在 Windows 11 on Arm 上验证。本地 OCR 需要 MSIX 包身份及系统语言资源。以下截图全部使用合成示例。

## 一个托盘工具，三个快捷入口

| 功能 | 默认快捷键 |
| --- | --- |
| 文件搜索 | **Alt+Q** |
| 剪贴板历史 | **Alt+W** |
| 截图 | **Alt+S** |

悬停功能入口显示当前快捷键，可在设置中修改；右上角 GitHub 图标一键打开当前项目。

## 独立文件搜索

![文件搜索](docs/images/files.png)

独立磁盘索引，后台建库时仍可查询已有条目。支持完整结果集排序、滚动续载及有界缓存，默认显示名称、目录、大小和本地修改时间；文件夹大小栏留空，旧索引的时间元数据在后台补齐。

名称双击定位，目录双击复制完整文件路径；支持系统右键、多选、拖出、过滤与导出。搜索示例：`report 2026`、`ext:pdf`、`type:folder`。

## 长期保留剪贴板历史

![剪贴板历史](docs/images/clipboard.png)

原格式保存文字、图片、HTML/RTF 和文件列表，支持连续去重、搜索与收藏，不因记录时间久就自动删除。内容按需读取，数据保存在磁盘。

![浮动预览](docs/images/clipboard-preview.png)

点击记录浮动预览，可滚动、选择文字；图片使用有界缩略图，不可呈现的格式显示详细信息。Alt+W 调起后按 Enter 可粘贴到此前窗口。

## 截图与标注

![截图编辑器](docs/images/capture.png)

自动选窗、放大镜、选区调整、形状、箭头、文字、画笔、马赛克和序号标注。白色分组工具栏，红叉取消，右侧绿色勾复制；撤销与重做使用快捷键。

![自动选窗与像素信息](docs/images/capture-hover.png)

按下左键前，选框跟随鼠标匹配应用窗口；同一窗口内移动也实时更新物理像素坐标和 HEX 色值。Ctrl+C 复制色值，单击选窗或拖动自定义选区。

## 本地文字识别

![本地 OCR](docs/images/ocr.png)

按需在独立进程运行 Windows OCR，长图分块识别，结果可选择及复制。在截图选区按 O，或导入图片文件、粘贴图片后识别。

## 原位置显示译文

![原图翻译](docs/images/translation.png)

在截图选区按 T 即可翻译，无需另开主界面；按住 Space 对照原图，译图仍可标注、复制、保存或贴图。可配置 Google 免费实验通道、DeepL API、Google 官方 API 和 LibreTranslate。

OCR 在本地运行，识别出的文字发送到所选翻译服务。免费实验通道可能变化或限流；请求失败不会自动转发给其他服务。

## 贴图与长截图

![置顶贴图](docs/images/pin.png)

贴图置顶，支持移动、缩放、透明度和滚动，随时对照图片内容。

![长截图](docs/images/scrolling.png)

在选区内手动滚动，按可信重叠拼接长图；固定标题或不明确的重叠会暂停拼接。

## 先录制，停止后保存

![录制控制条](docs/images/recording.png)

GIF / MP4 点击后直接录制并计时，可暂停、停止和取消；停止后选择保存位置与文件名，取消保存仍可重试。**MP4 默认录入系统播放声音**，包括网页直播声音，麦克风不启用；GIF 无声音。

实时录制范围显示绿色边框，暂停变琥珀色。窄边框不拦截鼠标、不写入录制文件，停止后在保存对话框出现前隐藏。录制帧流式写盘，避免将整段视频保存在内存中。

## 面向长期使用的资源管理

- 原生 C++20、Win32、Direct2D/DirectWrite、SQLite、WIC、Media Foundation 与 WASAPI，无需 Electron 运行时。
- 索引和历史在磁盘，列表缓存、图片与录制任务有明确预算。
- 后台索引分时让出 CPU，待机等待文件系统通知，OCR 与媒体编码按需启动。
- 更新沿用包家族数据目录，API Key 使用 Windows DPAPI 保护。

真正待机时持续占用 3% CPU 对后台工具偏高；首次索引、校准、OCR 与视频编码需要更多资源。可在“工具 → 索引与运行状态”确认当前阶段，详见[性能说明](docs/PERFORMANCE.md)。上述设计和基准不保证多年永不崩溃或任何规模都达到相同响应速度。
